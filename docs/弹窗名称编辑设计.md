# 坐标弹窗名称编辑 · 最小侵入交互设计

> 目标：在坐标弹窗（marker-popup）内支持"点击名称 → 改名 → 保存后地图标记同步更新"。
> 约束：**不改动任何现有 UI 外观与现有类**；只新增元素、新增类、新增事件。默认（非编辑）状态下页面观感与现状完全一致。

---

## 0. 现状确认（代码依据）

| 项 | 位置（memo-home.html） | 现状 |
|---|---|---|
| 弹窗标题 | L3157 `<div class="popup-title" id="popupTitle">` | 15px / 700 / #FAF5EC，max-width 200px，超出省略号（L1342-1346、L1377-1383） |
| 标题行布局 | L3155-3171 `.popup-title-row` | `display:flex; justify-content:space-between`，两个子元素：标题 div + `.popup-title-right`（关闭键+导航键） |
| 图标按钮范式 | L1348-1375 `.popup-close` / `.popup-nav` | 24×24 圆角命中区，svg 14-15px、stroke 2；hover 态 #F0A040 + rgba(240,160,64,0.2) 底，active scale(0.9) |
| Toast 体系 | L3498-3531 `showToast(msg,type,duration)` | 毛玻璃居中，图标渐变 #F0A040→#D4691C，文案带 emoji 前缀（📍🧭🗑📷📄✓ 等），成功默认 2000ms |
| 真实数据源 | L3613-3627 `detailLevels`（唯一真实数据源为 level 3） | 标记对象 `{title, lng, lat, date, count, color}`；删除按 title 全层级 findIndex（L4609-4616） |
| 照片数据 | L3569 `photoData[title]`、L4060 `localUploadedPhotos[title]` | **以 title 为 key**；删除标记时同步 delete（L4616） |
| 聚合点 | L3748 标题为合成值 `mainItem.title + '及周边'`；L4053 `marker.dataset.subPoints` | 聚合弹窗照片按各子点 title 合并；聚合标题每次渲染重新生成，**不持久** |
| 弹窗互斥 | L3536 `closeAllOverlays()` | 点遮罩关闭弹窗；marker 点击入口 showPopup（L4038） |
| 导航读取 | L4404 `popupNav` 读取 `popupTitle.textContent` | 改名后自动生效，无需改动 |

关键结论：**title 是全局身份键**（标记查找、照片分组、搜索定位均按 title）。改名必须同步迁移数据，见第 4、5 节。

## 1. 编辑入口设计

### 1.1 位置
铅笔图标紧贴标题文本右侧（在 `.popup-title-row` 的**第一个子元素内部**），与标题同一行、垂直居中对齐。理由：

- 放进 `.popup-title-right` 会混入关闭/导航按钮组，语义错误；
- 直接作为 `.popup-title-row` 第三子元素会破坏 `space-between` 布局——**必须用一层包裹容器**（见 4.1），默认态外观零变化。

### 1.2 规格

| 属性 | 值 | 依据 |
|---|---|---|
| 图标 | 铅笔 SVG（lucide 风格，viewBox 24，stroke 2，圆角端），14×14px | 与 `.popup-close` svg 同级 |
| 命中区 | 24×24px、border-radius 50% | 与 `.popup-close`/`.popup-nav` 完全一致（≥ 触屏最小命中 20px） |
| 默认色 | `rgba(255,255,255,0.45)` | 略弱于关闭键 0.6，体现"次要操作" |
| hover / 触摸态 | 颜色 `#F0A040`，背景 `rgba(240,160,64,0.15)` | 沿用 `.popup-nav` hover 范式 |
| active | `transform: scale(0.9)` | 与 `.popup-nav:active` 一致 |
| 可见性 | **常驻可见**（非 hover 才出现） | 移动端无 hover，常驻低透明度保证可发现性 |

### 1.3 附加命中区（推荐）
标题文本本身也可点击进入编辑（与铅笔同事件）。原因：底部弹窗标题 15px 字号偏小，仅 24px 铅笔命中区在触屏上局促；让标题整体可点可获得更大热区。铅笔仍保留，作为视觉可发现性锚点。

## 2. 编辑交互流程

### 2.1 状态与切换

```
[展示态] ──点击铅笔/标题──▶ [编辑态]
[编辑态] ──回车 / 点✓ / 失焦──▶ 保存（改名并刷新）
[编辑态] ──Esc──▶ 取消（恢复原名，无任何副作用）
```

- **进入**：`popupTitleInput.value = 当前名称`；给弹窗根元素加状态类 `.editing`；`input.focus()` + `select()`（全选便于直接重输）。
- **编辑态下**：标题 div 隐藏、铅笔隐藏、✓ 确认按钮出现（三者全部由 `.marker-popup.editing` 状态类驱动，**不触碰现有类的默认样式**）。

### 2.2 确认方式（推荐：三通道并存）

| 通道 | 行为 | 推荐理由 |
|---|---|---|
| **回车（Enter）** | 保存 | 键盘用户主路径，符合输入习惯 |
| **✓ 确认按钮** | 保存 | 触屏无键盘回车时的显式确认 |
| **失焦（blur）** | 保存 | 覆盖"点遮罩关弹窗""点关闭键"等离场路径，**保证不丢编辑内容** |

> 失焦保存的原因：点遮罩关闭弹窗是用户主意图（关弹窗），此时若静默丢弃改名会造成挫败感；先触发 blur 保存再关闭，行为最安全。`commitEdit` 做幂等守卫（非编辑态直接 return）以兼容"回车后 blur 二次触发"。

### 2.3 取消方式
- **Esc**：恢复原名，退出编辑态，不发 toast。
- 取消仅在 Esc 时存在；点外部视为"保存并关闭"（见 2.2 失焦通道）。

### 2.4 输入约束
- `maxlength="20"`（地名足够；配合现有 200px 省略号不会破坏布局）。
- **中文输入法兼容**：Enter 提交前判断 `e.isComposing`（组合键状态），避免选词回车误提交。

## 3. 保存反馈

| 场景 | Toast 文案 | type | 依据 |
|---|---|---|---|
| 保存成功 | `✏️ 名称已更新` | success（默认 2000ms） | 与 `🗑 已删除标记` 同句式 |
| 名称为空（拒绝保存） | `⚠️ 名称不能为空` | warning | 与 L5160 `⚠️ 最多上传9张…` 同 warning 范式 |
| 名称未变化（未提交） | 无 toast，仅退出编辑态 | — | 避免无意义打扰 |
| 取消（Esc） | 无 toast | — | 取消是静默操作 |

统一用 `showToast(msg, type, duration)` 既有接口，无需改动 toast 组件。

## 4. 实现要点（前端落地清单）

### 4.1 DOM 修改（唯一一处，L3155-3171 `.popup-title-row` 内）

**只做包裹 + 追加**，不改任何现有元素属性：

```html
<div class="popup-title-row">                                          <!-- 不动 -->
  <div class="popup-title-wrap">                                        <!-- 新增：包裹层 -->
    <div class="popup-title" id="popupTitle">西湖断桥</div>             <!-- 原样保留 -->
    <input type="text" class="popup-title-input" id="popupTitleInput"
           maxlength="20" autocomplete="off" style="display:none">      <!-- 新增：常驻 DOM，默认隐藏 -->
    <button class="popup-title-edit" id="popupTitleEdit" title="编辑名称" aria-label="编辑名称">
      <!-- 铅笔 SVG 14px stroke2 -->                                    <!-- 新增 -->
    </button>
    <button class="popup-title-confirm" id="popupTitleConfirm" title="保存"
            aria-label="保存" style="display:none">                     <!-- 新增：✓ SVG 14px stroke2 -->
      <!-- ✓ 图标 -->
    </button>
  </div>
  <div class="popup-title-right">…</div>                                <!-- 不动 -->
</div>
```

- `.popup-title-row` 仍是两个子元素（wrap + title-right），`space-between` 布局不受影响。
- input 常驻 DOM（`display:none`）而非动态创建：避免反复绑定事件与移动端键盘拉起不稳定。

### 4.2 新增 CSS 类（全部新类名，默认态下零视觉变化）

```css
/* 包裹层：不破坏 title-row 布局 */
.popup-title-wrap { display: flex; align-items: center; gap: 6px; min-width: 0; flex: 1; }

/* 铅笔 / 确认按钮：完全复用 popup-close 的尺寸范式 */
.popup-title-edit, .popup-title-confirm {
  width: 24px; height: 24px; flex-shrink: 0;
  display: flex; align-items: center; justify-content: center;
  cursor: pointer; border-radius: 50%;
  color: rgba(255,255,255,0.45);
  transition: all 0.2s;
}
.popup-title-edit:hover { background: rgba(240,160,64,0.15); color: #F0A040; }
.popup-title-edit:active, .popup-title-confirm:active { transform: scale(0.9); }
.popup-title-edit svg, .popup-title-confirm svg { width: 14px; height: 14px; stroke-width: 2; }

/* 输入框：字号/字重/字色与 popup-title 完全一致，无跳变 */
.popup-title-input {
  display: none;
  font-size: 15px; font-weight: 700; color: #FAF5EC;
  background: rgba(255,255,255,0.06);
  border: 1px solid rgba(240,160,64,0.55);
  border-radius: 6px; padding: 2px 6px;
  max-width: 200px; min-width: 0; flex: 1;
  outline: none; caret-color: #F0A040;
}

/* 编辑态切换：状态类挂在 marker-popup 根元素上，默认态零影响 */
.marker-popup.editing .popup-title { display: none; }
.marker-popup.editing .popup-title-edit { display: none; }
.marker-popup.editing .popup-title-confirm { display: flex; }
.marker-popup.editing .popup-title-input { display: block; }
```

### 4.3 JS 事件绑定（建议放在 L4404 popupNav 绑定附近统一注册）

| 绑定 | 行为 |
|---|---|
| `popupTitleEdit` click（含 `popupTitle` 点击，事件委托或双绑） | `enterEdit()` |
| `popupTitleInput` keydown | Enter 且 `!e.isComposing` → `commitEdit()`；Escape → `cancelEdit()` |
| `popupTitleInput` blur | `commitEdit()` |
| `popupTitleConfirm` click | `commitEdit()` |

三个函数 + 一个核心迁移函数：

```
enterEdit()  → 若铅笔被隐藏（聚合点）则 return；input.value = 当前标题；add('editing')；focus()+select()
cancelEdit() → remove('editing')（恢复原名显示）
commitEdit() → 非编辑态 return（幂等）；newTitle = input.value.trim()
               空 → showToast('⚠️ 名称不能为空','warning')，保持编辑态
               与旧名相同 → cancelEdit()，无 toast
               否则 → renameMarker(旧名, 新名)

renameMarker(oldTitle, newTitle):
  1. 遍历 detailLevels 各层级 findIndex(m => m.title === oldTitle) 逐个改名
     （对齐 L4609-4614 删除逻辑的遍历写法）
  2. photoData 迁移：photoData[newTitle] = photoData[oldTitle]; delete photoData[oldTitle]
     （对齐 L4616 的 delete 语义；若 key 不存在则跳过）
  3. localUploadedPhotos 同样迁移（L4060 读取处）
  4. renderMarkers(currentDetailLevel)   → 地图标记 dataset.title 重建为新名
  5. popupTitle.textContent = newTitle   → 弹窗保持打开且标题即时更新
  6. remove('editing')
  7. showToast('✏️ 名称已更新', 'success')
```

### 4.4 showPopup 内的一个隐藏逻辑（L4038 函数末尾）
```js
// 聚合点标题为系统合成值（"XX及周边"，每次渲染重建，不持久），不提供编辑入口
popupTitleEdit.style.display = marker.dataset.subPoints ? 'none' : 'flex';
```

## 5. 边界情况

| # | 场景 | 处理 | 说明 |
|---|---|---|---|
| 1 | **空名称** | 拒绝保存，保持编辑态，`⚠️ 名称不能为空` | trim 后判断；拒绝时输入框不失焦（blur 触发后需重新 focus，或延迟校验） |
| 2 | **超长名称** | `maxlength=20` 硬截断；显示端沿用现有 200px 省略号 | 输入阶段限制，展示阶段已有兜底，无需新样式 |
| 3 | **聚合点**（subPoints 存在） | 隐藏铅笔，不可编辑 | 聚合标题是每次渲染的合成值，改名不持久且无意义（照片存在各子点 key 下）。用户可放大地图进入独立点后改名 |
| 4 | **照片分组联动** | **必须迁移 `photoData[oldTitle]` 与 `localUploadedPhotos[oldTitle]` 两个 key** | 这是最易漏的点：漏迁移则照片在新名下"消失"。聚合弹窗按子点 key 合并，不受改名影响 |
| 5 | **地图标记同步** | `renderMarkers` 重建 marker，dataset.title / `_data.title` 自动为新名 | 重新打开弹窗时 `photoData[newTitle]` 正常关联 |
| 6 | **搜索 / 定位 / 导航联动** | 均按 title 在 detailLevels 中查找（locateToMarker / navigateToMarker），改名后自动生效 | 无需改动；`popupNav` 读取 `popupTitle.textContent` 也自动用新名 |
| 7 | **重名** | 保持现状语义（系统本就允许同名点，删除按首个匹配），不增加重名校验 | 可选非阻塞扩展：保存前检测到同名时 `⚠️ 该名称已存在`。最小方案下不引入 |
| 8 | **编辑中关弹窗**（点遮罩 / 点关闭键） | blur 先于关闭触发 → 保存后关闭，不丢修改 | 依赖 2.2 失焦保存通道；实现时确认 blur 顺序（mousedown 遮罩 → blur → click 关闭） |
| 9 | **中文输入法** | Enter 提交前判断 `e.isComposing` | 防止选词回车误提交（移动端中文输入常见问题） |
| 10 | **同名迁移碰撞** | `photoData[newTitle]` 若已存在会覆盖合并 | 与现状"同名点照片本就共用 key"语义一致；若采纳第 7 条重名校验则不再发生 |

## 6. 验收标准（最小化检查单）

1. 默认态（非编辑）下，弹窗与现有外观逐像素一致——仅标题右侧多一个低透明度铅笔。
2. 点铅笔或标题进入编辑，输入框与标题同字号同字重，无布局跳变。
3. 回车 / ✓ / 失焦均可保存；Esc 取消。
4. 保存后：地图标记、弹窗标题、搜索、导航、重新打开弹窗的照片分组全部使用新名称。
5. 改名后该点的照片仍在（key 迁移成功）。
6. 聚合点（XX及周边）不显示编辑入口。
7. 空名称被拒绝并提示；超长输入被 maxlength 截断。
8. toast 文案与现有 emoji 体系风格一致。
