# 雷达·附近摄影师实时位置：框架与方案（docs/雷达功能方案.md）

> v2（2026-09-20，已按王总 7 项意见修订）· **待王总最终拍板后实施**（先方案后实施）
> 范围：全 App 底部中间键「相机 → 雷达」＋ 相机入口迁「我的」页 ＋ 摄影师实时位置上图 ＋ 查看端雷达模式
> 分期：一期「前台版」（纯 H5）/ 二期「后台版」（UTS 插件，微信同级）

## 1. 一句话结论

全 App 底部中间键由相机改为雷达：点击后地图上实时显示**附近正在出片的工作模式摄影师**（紫色点＋脉冲、可点开主页）；相机入口迁到「我的」页最下方长条形按键。一期纯 H5 实现（App 开着才上报），**1–2 天**可跑通体验闭环；二期加一块 `uts-location` 原生插件（照录屏插件模板做），锁屏也能持续上报，达到**微信同级**的后台共享能力（约 **1 周**）。

## 2. 与探索模式的区别（定调）

| 维度 | 探索模式（现有） | 雷达模式（新增） |
|---|---|---|
| 看什么 | 作品：照片坐标（静态） | 人：摄影师实时位置（动态） |
| 数据 | 工作模式摄影师上传的作品 | 工作模式手机的实时位置 |
| 点位 | 纯紫点（#5E35B1） | 紫色点＋脉冲动效（一眼区分） |
| 刷新 | 打开时拉取 | 每 5–10 秒刷新、平滑移动 |
| 入口 | 右上角探索键 | 底部中间键（全 App 一致） |

## 3. 总体框架（三端数据流）

```
摄影师端                        后端（Sealos）                  查看端
工作模式开＋App 前台   ──上报──▶  每人只存「最后位置＋时间」        雷达模式开
（二期：锁屏也可）      POST      超 60 秒未更新＝自动离线        每 5–10 秒拉取
每 5–10 秒一次                   （查询时自动摘点）        ◀──GET──
                                                           附近半径内在线摄影师 → 紫点
```

三个环节：
1. **上报**：摄影师端（登录＋工作模式＋未隐身）每 5–10 秒上报一次坐标（含精度）；
2. **中转**：后端每人只存一条「最后位置＋时间」，超过 60 秒未更新＝离线，查询时自动排除；
3. **展示**：查看端开启雷达后，每 5–10 秒拉取半径内在线摄影师，渲染紫点。

## 4. 分期路线（含验收标准）

### 一期·前台版（先做；预估 1–2 天）

- 摄影师端：App 在前台才上报（纯 H5：`watchPosition`＋节流上报），零原生改动；
- 后端 2 个新接口＋隐身字段；
- 前端：
  - 首页/联机/消息/我的 四处底部导航中间键：相机 → 雷达（图标带扫描动效）；
  - 相机入口：「我的」页最下方新增**长条形按键**（点击＝系统相机直拍，复用现逻辑）；
  - 「我的」页模式切换栏「拍摄模式」标题行右侧新增**雷达隐身开关**（位于生活/工作 tab 上方）；
  - 首页雷达模式全套 UI（紫点＋脉冲、半径圈、小卡片、横幅、空态、与探索/灵感互斥）；
- **验收**：两台手机实测——A 开工作模式，B 开雷达能看到 A 的紫点并点开主页；A 关闭/隐身/超 60 秒后点消失；A 仍可从「我的」页长条键直接拍照。

### 二期·后台版（预估约 1 周；加原生插件）

- 新增 `uts-location` 插件：照 `uts-screencontrol` 录屏模板（前台服务＋常驻通知＋Android 14 服务类型声明），锁屏/切后台继续上报；
- 附「权限引导」页（自启动 / 省电白名单 / 始终允许，逐厂商指引）；
- **验收**：A 锁屏 10 分钟，B 端仍看到 A 位置持续更新（微信同级体验）。

## 5. 详细设计

### 5.1 摄影师端（上报）

- 激活：登录＋工作模式＋未隐身＋（一期）App 前台；
- 频率：5–10 秒/次；含精度 accuracy；静止降频（二期在插件内做）；
- 停止：关工作模式 / 开启隐身 /（一期）退后台关 App → 由 60 秒心跳兜底摘点；
- 坐标：WGS84（与天地图一致，页面已有 GCJ→WGS84 转换函数）。

### 5.2 后端（新接口，按 api.md 规范补章节）

- `POST /api/v1/radar/report`：{lng, lat, accuracy} → 更新本人「最后位置＋时间」；
  - 限流（≤1 次/3 秒）；跳变校验（物理不可能的速度直接丢弃）。
- `GET /api/v1/radar/nearby?lng=&lat=&radius=`：返回列表（userId / 昵称 / 头像 / 坐标 / 距离 / 最后上报时间）；
  - 过滤：排除自己、仅工作模式、未隐身、最后上报 <60 秒、半径内。
- 隐身字段：User 上加 `radarHidden`（默认 false）；切换接口实施时并入现有资料更新或独立小接口；
- 存储：新增 `radar_locations` 集合（userId 唯一 / lng / lat / accuracy / updatedAt），查询复用 `utils/geo.js`；
- 不做位置历史（每人只有一条，随更新覆盖）。

### 5.3 查看端（雷达模式）

- 中间键：相机 → 雷达（**首页/联机/消息/我的 四处统一**）；图标带扫描动效，与右上探索键区分；
- 相机入口：「我的」页最下方长条形按键（新入口，点击复用 `captureWithSystemCamera`）；
- 进入雷达：定位到我 → 画雷达半径圈 → 加载附近摄影师；
- 点位：紫色＋脉冲动效；
- 刷新：5–10 秒轮询；点位用 CSS transition 平滑移动（Leaflet 本地源码已验证可行）；新增/消失淡入淡出；
- 交互：点紫点 → 小卡片（头像/昵称/距离/最后更新）→「进主页」（复用 openUserProfileById）；
- 状态：顶部横幅「雷达模式 · 找到 N 位摄影师」；空态「附近暂无摄影师在出片」；与探索/灵感互斥。

### 5.4 隐私与合规

- **雷达隐身开关**：「我的」页模式切换栏「拍摄模式」标题行右侧、生活/工作 tab 上方；
  - 开启 ＝ 立即停止上报 ＋ 后端查询同时过滤（双保险）；关闭 ＝ 恢复上报；
  - 默认关闭（工作模式即可见，文案告知：开启工作模式即表示位置对雷达可见）；
- 仅登录用户可查询；上报限流＋跳变校验；
- 上架前：隐私政策补「位置信息」收集用途条款。

## 6. 难点与兜底（含极限情况）

| # | 极限场景 | 兜底 |

| 3 | 弱网 / 定位漂移 | 上报退避重试；查看端失败保留上次画面 |

| 5 | 恶意假位置 | 限流＋跳变校验；接受残余风险 |
| 6 | 冷启动点位少 | 空态文案；可选「最近 30 分钟活跃」兜底（二期） |

## 10. 方案依据（技术实锤清单）

- `uts-screencontrol` 插件＝前台服务模板（本工程云打包已用通，Kotlin 直接复用改造）；
- 后端可复用：WS 基建（chat.ws.js）、地理查询（utils/geo.js）、探索半径查询模式；
- 前端可复用：探索模式渲染/交互全套、openUserProfileById、定位链路、captureWithSystemCamera；
- Leaflet 1.1.1 本地源码：点位 translate3d 定位 → CSS transition 平滑移动可行；
- Android 官方：前台服务 location 类型＋FOREGROUND_SERVICE_LOCATION（已核对）；
- uni-app 官方：`startLocationUpdateBackground` 不支持 App 平台 → 后台能力必须走原生插件。
- 实测核对：「我的」页=profile-prototype.html，模式切换栏=「拍摄模式」标题行＋生活/工作 tab，隐身键落点已确认；四处底部导航均带中间相机键（centerBtn/cameraBtn）。
