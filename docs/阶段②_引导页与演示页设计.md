> 类型：视觉/交互设计规范（文本级，可直接交开发实施）

### 0.2 文案体系（emoji 前缀约定）

现有已用：`📸 拍摄` `📍 坐标归类` `✅ 连接成功` `⚠️ 警告` `🔗 连接` `💬 客服`

新页面沿用并扩展：

| emoji | 语义 | 使用场景 |
|---|---|---|
| 📡 | 热点 / 网络 / 距离 | 步骤 1、2 米提示 |
| 🔑 | 账号 / 凭据 | 参数区、步骤 3 清单 |
| ⚙️ | 相机设置 | 步骤 3 标题、清单项 |
| 📋 | 日志 / 复制 | 日志区标题、复制反馈 |
| 🖼️ | 照片 / 相册 | 接收列表、空状态 |
| 📤 | 传输中 | 日志"传输开始"行 |
| 🔁 | 更换 / 重新生成 | 账号换号按钮、反馈 |
| ▶ / ⏸ | 启动 / 停止 | 演示页主操作 |
| ⏱️ | 时间 / 超时 | 6 小时限制提示 |
| ℹ️ | 系统提示（中性） | 日志系统行 |

规则：每条 toast / 提示条 / 日志行都以一个 emoji 开头；正文不超过 30 字，一行放不下才换行；emoji 与文字之间空一格（与联机页 `✅ 相机连接成功！` 一致）。

### 0.3 与插件层的状态对齐（实现关键）

演示页的状态区、日志区**直接映射插件契约**，页面不做二次状态推断：

| 插件信号 | 页面表现 |
|---|---|
| `phase: idle` | 状态区"未启动"（灰点） |
| `phase: starting` | 状态区"启动中…"（橙点脉冲 + 按钮转圈） |
| `phase: running` + `serverInfo{ip,port}` | 状态区"接收中"（绿点脉冲）+ 参数区回填 IP/端口 |
| `phase: stopping` | 状态区"正在停止…"（灰点，按钮禁用） |
| `phase: error` + `{code,message}` | 状态区切"已停止"，toast + 日志追加错误行 |
| 事件 `connected` | 日志绿行 |
| 事件 `transferring{name,size}` | 日志橙行 |
| 事件 `fileReceived{meta}` | 日志米色行 + 接收列表插入新项 + 计数 +1 |
| 事件 `disconnected` | 日志次级行 |
| 事件 `error{code}` | 日志红行（1007 超时 / 1008 传输失败走这里） |

## 1. 引导页设计（佳能相机 FTP 3 步引导）

### 1.1 页面骨架（自上而下）

1. **顶部栏**：左"关闭/返回"（点击回联机页，toast 无），标题"相机 FTP 直连"，右侧"跳过"文字按钮（灰字，点击直入演示页）
2. **步骤指示器**：3 段水平指示（见 1.2）
3. **步骤内容区**（可滚动）：每步一张"步骤卡"（复用 `.feature-card` 风格）+ 内联提示条
4. **底部操作区**：固定底部，"上一步 / 下一步"或"开始接收"主按钮
5. 全站统一 toast 组件

### 1.2 步骤指示器

- 3 个圆点（10px）+ 连线段（24px），水平居中
- 已完成：橙色实心（#F0A040）+ 对勾；当前：橙色描边 + 白色内点脉冲（复用脉冲动画）；未到：`rgba(245,223,192,0.3)` 空心
- 当前步骤编号上方显示小标题（12px，如"01 热点准备"），保持总宽不变，仅文字切换，避免跳动

### 1.3 三步文案稿（含信息层级）

每步的信息层级统一为三层，模板如下：

- **关键信息**（18px/700 `#F5DFC0`）：该步必须完成的核心动作
- **辅助信息**（12px `rgba(245,223,192,0.6)`）：解释性文字，为什么/会怎样
- **操作按钮**（主按钮规格）：底部主操作 + 次操作（文字链）

---

**第 1 步 · 📡 手机热点准备**

- 步骤标题：`📡 开启手机热点`
- 关键信息：`在系统设置中打开"个人热点"，让相机能搜到你的手机`
- 辅助信息：`热点名称记不记都行，相机端需要手动输入`（缓解"记热点名"负担）
- 警示条（⚠️）：`⚠️ 建议关闭热点的"自动关闭/无连接超时"功能，避免拍摄中途断网`
- 距离提示（📡，图标+文字）：`📡 拍摄时请保持相机与手机距离 2 米以内，中间不要遮挡`
- 操作按钮：主按钮 `下一步`；无次操作
- 隐藏检查（可选，推荐做）：点击"下一步"前检查系统热点是否开启（Android 可查热点状态；查不到则跳过检查不阻塞流程）

**第 2 步 · 🔗 查看接收信息**

- 步骤标题：`🔗 查看接收信息`
- 关键信息：`App 已生成相机需要输入的连接信息（自动获取，无需配置）`
- 信息卡（三行，左标签右值，标签 12px/60%，值 15px/700 `#F0A040`——对齐工作台参数样式）：
  - `服务器地址` → IP（自动获取）
  - `端口` → `21`（固定，说明"相机默认端口，无需修改"）
  - `账号` → `用户名 / 密码` 两行显示（随机生成）
- 辅助信息：`相机端只需照抄这三项；账号由 App 随机生成，用完随时可换`
- 操作按钮：主按钮 `下一步`；次操作（文字链）`🔁 换一个账号`
- 本条信息在本步骤内与演示页**实时联动**：用户在此换号，演示页同步更新

**第 3 步 · ⚙️ 相机端 FTP 设置**

- 步骤标题：`⚙️ 在相机上设置 FTP`
- 关键信息：`按下面的清单在相机菜单里逐项设置（以佳能菜单为例）`
- 清单卡（复选式清单：每项左圆框待勾选，点击打勾并变橙，供用户逐项确认）：
  1. `相机菜单 → 无线通信设置 → FTP 传输设置`
  2. `传输模式：保持默认「主动」`
  3. `服务器地址：输入 App 显示的 IP`
  4. `端口：21`
  5. `用户名 / 密码：照抄 App 显示的随机账号`
- 警示条（⚠️，清单第 2 项展开时同步显示）：`⚠️ 「被动模式」默认关闭——若开启接收后一直传输失败，请回到这里将传输模式改为「被动」再试`
- 预期管理条（📸，位于清单下方，独立强调色或橙色描边）：`📸 先在 App 点「开始接收」，再拿起相机开拍——未开启接收时，照片只存在相机卡内，不会传到手机`
- 操作按钮：主按钮 `✅ 开始接收`（跳转演示页并自动启动服务）；次操作（文字链）`跳过引导，直接进入接收页`

### 1.4 三种内联提示条规范（全页复用，引导页 + 演示页通用）

| 类型 | 视觉 | 文案规则 |
|---|---|---|
| 警示条 ⚠️ | 底 `rgba(244,67,54,0.08)`，描边 `rgba(244,67,54,0.35)`，左侧 3px 红色竖条，圆角 10px | 只放"做错了会怎样 + 怎么救"，≤2 行 |
| 预期/说明条 📸 | 底 `rgba(240,160,64,0.12)`，描边 `rgba(240,160,64,0.3)`，左侧 3px 橙色竖条 | 改变用户默认预期（如"先接收再开拍"） |
| 中性提示 ℹ️ | 无底色，仅 12px 弱文字 | 补充说明，绝不承载警告 |

## 2. 接收演示页设计（插件 example 页，未来产品页）

### 2.1 页面骨架（自上而下）

1. **顶部栏**：返回 + 标题"FTP 接收演示"
2. **状态区**（见 2.2）
3. **参数区**（见 2.3）
4. **日志区**（见 2.4）
5. **接收列表**（见 2.5）
6. 底部无固定栏（内容可滚到底），统一 toast

页面外壳与联机页一致：深色内容底（`#0a0a0a`），顶部状态栏复刻联机页。

### 2.2 状态区

深色面板卡（复用 `.connect-options` 面板风格：`rgba(28,15,8,0.5)` 底 + 米棕描边 + 圆角 16px），内部一行三组：

| 状态 | 点 | 主文案 | 副文案（12px 60%） | 操作 |
|---|---|---|---|---|
| 未启动 `idle` | 灰点 `rgba(245,223,192,0.3)` | `未启动` | `开启后相机才能连接上传` | 主按钮 `▶ 启动接收` |
| 启动中 `starting` | 橙点脉冲 | `启动中…` | `正在绑定端口` | 按钮禁用（转圈） |
| 接收中 `running` | 绿点 `#4CAF50` 脉冲（复用现有脉冲动画） | `接收中` | `已运行 00:12:34 · 已接收 3 张` | 次级按钮 `⏸ 停止接收`（红字） |
| 已停止 `error/stopping` | 灰点 | `已停止` | 错误态：`错误码 1007：…` 弱红字 | 主按钮 `▶ 重新启动` |

- 接收计数数字用 `#F0A040` 700 加粗（对齐工作台参数值样式），新照片到达时计数做一次 0.3s 弹跳动画（复用 `@keyframes pop` 思路）
- 运行时主文案左侧放小相机图标（复用联机页 `cam-icon`，连接后变绿 `#4CAF50`）

### 2.3 参数区

标题行：`🔑 连接信息`（14px/600），右侧文字链 `🔁 换一个账号`

三列等宽卡（横排，窄屏可折为上下两行），每卡结构：

| 卡 | 值（15px/700 `#F0A040`） | 复制按钮 |
|---|---|---|
| 服务器地址 | `192.168.43.1`（`serverInfo.ip` 回填） | `复制` |
| 端口 | `21` | `复制` |
| 账号 | 两行：`用户名`（上）/ `密码`（下，中间圆点脱敏，点复制才显示明文并复制） | `复制` |

- 复制按钮：12px 描边小按钮（`rgba(240,160,64,0.15)` 底 + `#F0A040` 字，对齐联机页 `.top-btn`），图标 📋 + 文字"复制"
- 服务未启动时，参数区显示占位 `--`，复制按钮禁用（45% 不透明度）
- 账号密码脱敏：默认显示 `●●●●●●`，长按或点击"复制"后 toast 提示已复制（明文不落地展示，降低旁人偷瞄风险）

### 2.4 日志区

标题行：`📋 连接日志`（14px/600）+ 右侧文字链 `清空`（12px 60%，点击交互见 3.3）

日志面板：`rgba(28,15,8,0.5)` 底 + 米棕描边 + 圆角 12px，高约 160–180px，内部自动滚动（滚动条 3px，`rgba(212,165,116,0.3)`，对齐联机页 content 滚动条）

日志行格式：`[12:00:01] 📤 传输中：IMG_0001.jpg（2.4 MB）` —— 时间戳（12px 35%）+ emoji + 12px 文本，行距 20px，不换行超长截断（留 ellipsis 或单行滚动）

**事件 → 日志行配色映射**（颜色不承担唯一信息，emoji + 文案冗余表达）：

| 事件 | emoji | 颜色 | 文案模板 |
|---|---|---|---|
| 服务启动成功 | ✅ | `#4CAF50` 绿 | `服务已启动，等待相机连接` |
| `connected` | ✅ | `#4CAF50` 绿 | `相机已连接`（追加客户端 IP） |
| `transferring` | 📤 | `#F0A040` 橙 | `传输中：{name}（{size}）` |
| `fileReceived` | 📥 | `#F5DFC0` 米 | `已接收：{name}`（列表同步 +1） |
| `disconnected` | ℹ️ | `rgba(245,223,192,0.5)` 次 | `相机已断开` |
| `error` 1008 传输失败 | ⚠️ | `#F44336` 红 | `传输失败：请检查相机传输模式` |
| `error` 1007 超时 | ⏱️ | `#F44336` 红 | `服务被系统停止（超 6 小时），请重新启动` |
| 其他 `error` | ⚠️ | `#F44336` 红 | `错误码 {code}：{message}` |

日志上限：内存保留最近 200 行，超出丢弃最旧（UI 不卡顿）。

### 2.5 接收列表

标题行：`🖼️ 已接收照片` + 右侧计数徽标（`N`，橙底白字圆角胶囊，对齐工作台红色角标但用橙）

列表项（复用 `.connect-option` 行式结构）：左缩略图 56×56，圆角 10px，描边 `rgba(212,165,116,0.2)`，无图时用 `#1C0F08` 底 + 相机图标占位；中间主行 14px/600 `#F5DFC0` 文件名（超长单行截断）；副行 12px 60% `2.4 MB · 12:00:03`；行间 1px `rgba(212,165,116,0.12)` 分隔（对齐 `.connect-option +` 分隔）

新项插入方式：从顶部插入（最新在上），插入时 0.3s 上滑淡入（复用 `pop` 思路的入场动画），并自动滚动到可见区。

**空状态**：虚线描边框（`rgba(212,165,116,0.3)` 虚线）内居中：`🖼️ 等待照片传入…`（14px 60%）+ 副文案 `在相机上按一次快门，照片会实时出现在这里`（12px 35%）

### 2.6 接收列表项点击（演示页交互，可选做）

点击缩略图 → 半屏预览弹层（深色底，图片 contain 显示，右上角关闭），仅供演示验收，不进产品路线图。

## 3. 交互细节

### 3.1 复制按钮

- 点击任一项"复制" → toast 反馈，文案按项区分：
  - `✅ 已复制 IP 地址`
  - `✅ 已复制端口`
  - `✅ 已复制账号（含密码）`
- 复制成功后按钮 1.5s 内变 `✅ 已复制`（文字态，图标随换），防重复连点
- 剪贴板写入失败（低概率）→ toast `⚠️ 复制失败，请长按手动选择复制`
- 全参数一键复制（引导页第 2 步可选）：卡片右上角"复制全部"，产出格式：
  ```
  服务器：192.168.43.1
  端口：21
  账号：user / pass
  ```

### 3.2 随机账号重新生成

- 触发点：引导页第 2 步"换一个账号"、演示页参数区"换一个账号"，共用同一逻辑
- 服务未运行：直接换新账号 → toast `🔁 已生成新账号，相机端请按新账号填写`
- 服务运行中：先弹确认（居中弹窗，深色底 + 橙描边）：`⚠️ 换号后相机当前连接会立即断开，需在相机端重新填写账号。确定更换？` → `[确定更换] [取消]`
- 生成后旧账号立即失效（新账号写入插件下次 startServer 的 options）；引导页与演示页显示的账号必须同一数据源，保证一致

### 3.3 日志清空

- 点击"清空"直接清空显示，toast `📋 日志已清空`（日志非敏感、成本低，不做二次确认）
- 清空仅影响显示，不影响已接收照片列表与服务状态（toast 副文案不解释，避免啰嗦）
- 可选增强：清空按钮长按 0.5s 清空（防误触），短按仅滚动到底部——**不作为默认行为**，优先级低

### 3.4 启动前权限检查（Android 通知权限）

点击"启动接收"时按序检查，任一失败即中止启动并提示：

1. **Android 13+ 通知权限（POST_NOTIFICATIONS）**：未授权 → 弹窗：
   > `📢 需要通知权限`
   > `接收服务需要常驻通知才能持续运行；未授权时 App 在后台可能被系统暂停接收。`
   > `[去开启] [暂不]`
   - 点"去开启"：未二次拒绝前走系统授权弹窗；已拒绝过则跳应用系统设置页
   - 点"暂不"：不启动，回到未启动态
2. **（可选）热点状态提示**：检测到热点未开 → 提示条（不阻塞）：`📡 未检测到热点。请先开启手机热点，相机才能连上你`（引导页第 1 步已教过，此处只提醒）
3. **启动失败**（插件 reject，错误码 1000/1001/1005/1006）：toast + 日志红行 + 状态区回"未启动"，文案用错误码表对应提示（`端口被占用，请更换端口` / `系统拒绝了接收服务，请重启应用再试` / `存储空间不足，请清理后重试`）

### 3.5 接收超时（Android 15 六小时限制）

- 事实依据：Android 15（API 35）dataSync 前台服务约 6 小时上限（插件错误码 1007），超时服务自动停止
- **启动成功时**（每次启动后，toast 一次性提示）：
  > `⏱️ 提示：受系统限制，接收服务最长连续运行 6 小时，将自动停止。长时拍摄请到时重新启动接收。`
- **被系统停止时**（收到 1007 事件）：状态区切"已停止"，toast：
  > `⏱️ 接收服务已连续运行超 6 小时，被系统停止。重新点击「启动接收」即可继续。`
  - 日志追加红行（见 2.4 映射表）
- 不允许"延长"或"自动重启"承诺：文案只给"重新启动"一条出路，避免误导

## 5. 实施备注（可直接交开发）

1. **页面关系**：联机页"无线连接"入口 → 引导页（3 步）→ 演示页（example，未来产品页）。引导页可"跳过"直达演示页；引导第 3 步"✅ 开始接收"跳转演示页并自动 `startServer`
2. **状态接线**：演示页状态区绑定 `useFtpServer` 的 `phase` 五态；日志区逐条映射 `onEvent` 五类事件；参数区由 `serverInfo{ip,port}` 回填（未启动显示 `--`）；账号由业务层生成并随每次 `startServer(options)` 下发
3. **账号数据源唯一**：引导页与演示页共用一个 ref（账号 = `useFtpServer` 之外的独立 `account` ref，用户每次换号后作为 options.user/pass 传入），杜绝两页不同步
4. **文案常量**：本文所有 emoji 文案集中为一个 `ftpI18n` 常量对象，页面与插件提示共用，避免散落
5. **不做的（防蔓延）**：不做连接动画演示、不做照片预览编辑、不做多相机同时连接、不做历史会话恢复 UI（被 1007 停止后仅手动重启）；这些留待产品阶段
