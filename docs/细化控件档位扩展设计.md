# 细化程度控件·档位扩展设计（聚合方向多档）

> 需求来源：王总要求在地图细化程度控件处「增加多个聚合档位」，最大聚合档 = 青岛市与屏幕等大（约 zoom 9-10）；控件范围之外地图仍可继续缩小（行政聚合），控件不跟随。
> 约束：不改 UI、不减功能 —— 本方案视觉元素零新增、零删除，仅档位数量从 3 扩到 7（3 个圆点扩为 7 个圆点）。

---

## 1. 结论摘要（TL;DR）

| 决策点 | 方案 | 一句话理由 |
|---|---|---|
| 档位总数 | **7 档**（新增 4 个聚合档 + 保留原 3 档） | 38px 控件宽只放得下 7 个 3px 圆点（33px），8 个即满宽（38px）无余量 |
| 档位编号 | **数字重排为 1-7：1 = 最聚合，7 = 最细分** | + 号与数字增大方向一致（更细分）、- 号与数字减小方向一致（更聚合），圆点激活公式 `i < level` 原样可用 |
| 控件中央文字 | **保持数字**（9px/700，样式不动），档位名称走 toast | 38px 宽放不下中文标签（4 字≈36-40px 必溢出），数字+圆点已是成熟的「档位进度」视觉语言 |
| 档位名称体系 | 聚合档用**地理语义**（青岛/半岛/城市/区县），原 3 档沿用低（聚合）/中（默认）/高（细分） | 聚合档的本质是「看到多大范围」，地理名最直白，且「青岛全貌」正是王总自己定义的最大聚合档 |
| 控件内加减 | **单点步进 1 档，不做长按连续**；加/减按钮边界用 `disabled`（现有样式已有，opacity 0.3） | 7 档单步即 zoom 翻倍，够用；长按连续需新增定时器逻辑且易冲过头，非本期范围 |
| 到最大聚合档再点减号 | **a) 按钮禁用**（推荐）；地图手势缩到控件之下 → 控件钳位在档 1、地图继续行政聚合（控件不管，现有 renderMarkers 已支持） | 控件只管控件范围 [L1, L7]，地图范围 [3, 18] 与之解耦；disabled 是现有交互语言，零新 UI |
| 是否用分段条/进度条 | **不换**，保留现有圆点 | 分段条会替换现有外观（违反约束），且 38px 内 7 段更拥挤 |

## 2. 现状梳理（已读代码确认）

**控件位置**：右侧操作按钮列内，`#detailPlusBtn`（加）/ `#detailLevelText`（数字）/ `#detailDots`（3 个圆点）/ `#detailMinusBtn`（减）。

**视觉（memo-home.html L2901-2960）**：
- `.detail-control`：宽 38px、圆角 12px、奶油底 `rgba(255,250,242,.95)`、暖棕描边 `rgba(212,165,116,.3)`、模糊背景。
- `.detail-btn`：36×30px、图标色 `#8B5E3C`、hover `#E89020`、**disabled = opacity 0.3 + not-allowed**（现有，直接复用）。
- `.detail-level-text`：9px / 700 / `#1C0F08`。
- `.detail-dot`：3px 圆点，未激活 `rgba(155,123,90,.3)`，激活 `#E89020`。

**交互与逻辑**：
- `LEVEL_TO_ZOOM = { 1: 13, 2: 15, 3: 17 }`（L4754）；`ZOOM_TO_LEVEL`（L4755）。
- `setDetailLevel(level, syncMap)`（L4757-4785）：更新 `currentDetailLevel` → `updateDetailControl()` → 各模式重渲染 → `map.setZoom(LEVEL_TO_ZOOM[level])` → toast `names = { 1:'低（聚合）', 2:'中（默认）', 3:'高（细分）' }`。
- `updateDetailControl()`（L4366-4375）：中央数字 = `currentDetailLevel`；圆点 `i < currentDetailLevel` 点亮；`plus.disabled = level >= 3`、`minus.disabled = level <= 1`。
- 加/减点击（L4788-4800）：`if (freeMarkMode) return;` 后 `currentDetailLevel ± 1` 带边界判断。
- 地图 zoomend 同步（L7774-7780）：`ZOOM_TO_LEVEL(map.getZoom())` → `setDetailLevel(level, false)`。
- 地图：Leaflet，**minZoom 3 / maxZoom 18**；zoom 3-13 行政分级聚合（≤6 国家 / 7-10 省 / 11-13 城市），zoom 14+ 精细聚合。
- 初始 `currentDetailLevel = 2`（L3720）；自由标记模式锁定最细档（L4907-4909，`savedDetailLevelBeforeFreeMark = 2`，恢复时 `setZoom(LEVEL_TO_ZOOM[...])`）。

## 3. 档位方案：7 档（推荐）

### 3.1 档位表

| 档位 | 控件显示 | 档位名（toast/title 用） | 对应 zoom | 视野语义 |
|---|---|---|---|---|
| L1 | 1 | **聚合·青岛（全貌）** | 9 | 青岛市与屏幕等大 = 最大聚合档（王总定义） |
| L2 | 2 | **聚合·半岛（区域）** | 10 | 山东半岛/周边区域视野 |
| L3 | 3 | **聚合·城市（群）** | 11 | 城市级聚合点可见 |
| L4 | 4 | **聚合·区县（城镇）** | 12 | 区县/城镇级聚合点可见 |
| L5 | 5 | **低（聚合）** | 13 | 原 Level 1，语义不变 |
| L6 | 6 | **中（默认）** | 15 | 原 Level 2，语义不变，**默认档** |
| L7 | 7 | **高（细分）** | 17 | 原 Level 3，语义不变 |

- 聚合段 9→13 共 4 档、每档 zoom +1（视野逐级翻倍）；细分段沿用原 13→15→17（每档 +2）。新档落在行政聚合区间（11-13 城市级 / 7-10 省级）内，与现有行政分级渲染自然衔接。
- 12 与 13 两档相邻但不等价：13 是「现有精细聚合」锚点（原 L1），12 是新引入的过渡聚合档，视觉上表现为「聚合点更少、更偏城镇级」。

### 3.2 为什么是 7 档，不是更多

- **宽度硬约束**：控件 38px，圆点 3px + 间距 2px。7 个 = 3×7 + 2×6 = **33px ≤ 38px（有余量）**；8 个 = 38px 顶满，视觉贴边且与容器圆角/内边距冲突。7 档是此尺寸下的舒适上限。
- **语义对齐**：聚合方向 4 档（青岛/半岛/城市/区县）+ 原 3 档 = 7，正好覆盖「王总要求的多几个聚合程度」且不稀释档位差异（每档 zoom 翻倍，档间体感差异明显）。
- **备选 6 档**（若王总嫌 7 档多）：去掉 L4（zoom 12），档位为 9/10/11/13/15/17，其余方案不变，改动点仅档位表。

### 3.3 被否决的方案（备查）

| 方案 | 否决理由 |
|---|---|
| 新增 Level 0 / -1 / -2 负档 | 中央显示「-1」违背消费级地图控件直觉；圆点激活公式 `i < currentDetailLevel` 对负数失效需重构；toast 文案难看。唯一优点是原 1/2/3 数字不变，但代价大于收益 |
| 一维分段条/进度条 | 替换现有圆点 = 改变外观（违反硬约束）；38px 宽内 7 段（≈4px/段）信息密度更低、更易误触 |
| 中央显示中文档位名（如「聚合·3」） | 9px 字号下 4 个中文≈36-40px，必溢出或需缩字号改字距 → 外观改变；与纯数字档位宽度不一致会「跳动」 |
| 长按连续步进 | 7 档单步即 zoom 翻倍，单点已够用；长按需新增定时器逻辑、易冲过头。**列为可选增强**（见 §6.4），本期不做 |

## 4. 档位名称体系

**核心原则：控件内数字（样式零改动）+ 名称走 toast 与 title（新增文案，非新 UI）**。

- 中央数字：1-7，纯数字，9px/700/`#1C0F08`，样式一行不动。
- Toast 沿用现有格式：`'🔍 细化程度：' + names[level]`，names 表见 §3.1。
- 聚合档名用**地理语义**（青岛/半岛/城市/区县），与王总「青岛市与屏幕等大」的心智模型一致；注意这是**视野近似提示，非行政区划绑定**（zoom 9 时行政聚合实际粒度是省级，但画面范围=青岛全貌），在开发注释中注明即可，无需向用户解释。
- 原 3 档名称「低（聚合）/中（默认）/高（细分）」**一字不改**（不减功能、不改语义）。
- 减号按钮 title「降低细化程度」、加号「提高细化程度」保持不动（最小侵入）；可选：边界时 title 动态变为「已到最聚合档位」（见 §6.3，非必须）。

## 5. 视觉规范

**零新增元素、零删除元素，唯一的视觉变化 = 圆点从 3 个变 7 个。**

| 元素 | 现状 | 变更 |
|---|---|---|
| `.detail-control` 容器 | 38px / 圆角12 / 奶油底 / 暖棕描边 | 不动 |
| `#detailPlusBtn` / `#detailMinusBtn` | 36×30 / `#8B5E3C` / hover `#E89020` / disabled `opacity:.3` | 不动（CSS 零改动） |
| `#detailLevelText` | 9px / 700 / `#1C0F08` | 不动（值域变为 1-7，均为 1 位数字，无宽度跳动） |
| `#detailDots` | 3 个硬编码 `<span class="detail-dot">` | **7 个**，建议由 JS 动态生成（`updateDetailControl` 或初始化时），HTML 原 3 个 span 可删可留（JS 先清空再填） |
| `.detail-dot.active` | `#E89020` | 不动；点亮逻辑 `i < level` 不变 |
| toast | 现有 `showToast` | 只换 names 表内容 |

- **档位指示**：圆点即档位指示器（从「3 段进度」自然延伸为「7 段进度」），不新增额外指示元素。7 个圆点 33px 宽 ≤ 38px 容器，无需改任何 CSS 尺寸。
- **无新增 hover/按下/禁用态样式**，全部复用现有类。

## 6. 边界交互

### 6.1 到最大聚合档（L1）再点减号 → **a) 按钮禁用**（推荐）

- 行为：`#detailMinusBtn.disabled = true`（现有样式 opacity 0.3 + not-allowed 直接复用），点击无效，无 toast、无抖动。
- 理由：
  1. 这是现有交互语言 —— 原 3 档时代减号在 L1 就是禁用（L4374），扩档后只是把 `<= 1` 换成 `<= MIN_LEVEL`，**对用户和代码都是零学习成本、零新 UI**。
  2. 「地图继续缩但控件不跟」（b 方案）只应发生在**地图手势**路径（捏合/滚轮），不应发生在控件按钮路径 —— 按钮是「控件自己的意图」，到了顶就该明确「到头了」；若按钮还能继续把地图缩下去而控件数字停在 1，用户会以为控件坏了。
  3. 禁用态即提示，无需 toast 打断（持续被禁的按钮 + 常亮数字已是「到顶」的静态反馈）。

### 6.2 地图手势缩出控件下限（z < 9）

- `ZOOM_TO_LEVEL` 底部**钳位**：z 3-9 一律返回 L1。控件显示停在「1」，减号保持禁用，控件不跟不闪。
- 地图继续缩小到 zoom 3 的行政聚合（国家/省/市）由现有 `renderMarkers` 的 `getAdminLevelForZoom(mapZoom)` 路径处理，**零新增逻辑** —— 这正是「控件之外地图可继续缩小（行政聚合，控件不管）」的既有行为，本次方案只负责「不把控件拽下去」。
- zoomend 同步（L7774-7780）不变，`setDetailLevel(1, false)` 会重渲染，行为与现状一致。

### 6.3 到最细档（L7）再点加号

- 与现状同构：`#detailPlusBtn.disabled = true`（原 `>= 3` 改 `>= MAX_LEVEL`）。
- 地图手势放大到 zoom 18：z 16-18 均归 L7，无钳位问题（maxZoom 18 已在 L7 带内）。
- **可选增强（非必须）**：边界时按钮 title 动态显示「已是最聚合/最细分档位」，1 行代码，无视觉变化。

### 6.4 长按连续步进（可选增强，本期不做）

- 若王总后续觉得 7 档单点太慢：加号/减号按下 500ms 后进入连续步进（interval ≈ 180ms，到边界自动停）。
- 实现提示：`pointerdown` 起定时器 + `pointerup`/`pointerleave` 清除，复用现有点击处理函数；不影响单点行为。**默认关闭**，用常量开关。

## 7. 实现要点（与现有 setDetailLevel 衔接）

### 7.1 改动清单

| # | 位置（memo-home.html） | 改动 |
|---|---|---|
| 1 | L4754-4755 | 常量化 + 数组化：`const LEVEL_MIN = 1; const LEVEL_MAX = 7;` `const LEVEL_ZOOMS = [9, 10, 11, 12, 13, 15, 17];`（索引 i 对应档位 i+1）；删除 `LEVEL_TO_ZOOM` 对象，`ZOOM_TO_LEVEL` 改为遍历钳位（见下） |
| 2 | L4757-4785 `setDetailLevel` | `map.setZoom(LEVEL_ZOOMS[level - 1])`；names 换成 7 项表（§3.1） |
| 3 | L4366-4375 `updateDetailControl` | 禁用边界：`plus.disabled = (currentDetailLevel >= LEVEL_MAX)`、`minus.disabled = (currentDetailLevel <= LEVEL_MIN)`；圆点循环 `i < level` **逻辑不变**，仅数量来自 LEVEL_MAX |
| 4 | L3069-3088 HTML | `#detailDots` 内 3 个 span 建议改为 JS 生成（初始化时 `detailDots.innerHTML = Array(LEVEL_MAX).fill('<span class="detail-dot"></span>').join('')`）；不改则手写 7 个 span（更繁琐，不推荐） |
| 5 | L3720 | 默认档 `let currentDetailLevel = 2` → `6`（原「中（默认）」在新编号下为 6） |
| 6 | L4900 / 4907-4909 / 4941 自由标记 | `savedDetailLevelBeforeFreeMark = 2` → `6`；锁定最细档 `currentDetailLevel = 3` → `LEVEL_MAX`（或 7）；恢复处 `setZoom(LEVEL_TO_ZOOM[currentDetailLevel])` → `setZoom(LEVEL_ZOOMS[currentDetailLevel - 1])` |
| 7 | L4788-4800 加/减点击 | 边界判断 `currentDetailLevel < LEVEL_MAX` / `> LEVEL_MIN`（其余不动，`freeMarkMode` 早退保留） |
| 8 | L7774-7780 zoomend 同步 | 只换 `ZOOM_TO_LEVEL` 实现（钳位版），调用处不动 |

### 7.2 关键代码示意

```js
// 档位表（数组索引 = 档位 - 1）
const LEVEL_MIN = 1, LEVEL_MAX = 7;
const LEVEL_ZOOMS = [9, 10, 11, 12, 13, 15, 17];
const LEVEL_NAMES = [
  '聚合·青岛（全貌）', '聚合·半岛（区域）', '聚合·城市（群）', '聚合·区县（城镇）',
  '低（聚合）', '中（默认）', '高（细分）'
];

// zoom → 档位（含底部钳位：z ≤ 9 归 L1，z ≥ 16 归 L7）
const ZOOM_TO_LEVEL = (z) => {
  let l = LEVEL_MIN;
  for (let i = 0; i < LEVEL_ZOOMS.length; i++) {
    if (z >= LEVEL_ZOOMS[i]) l = i + 1;
  }
  return l;
};
```

### 7.3 回归检查清单

- 默认进入：显示 6、6 个圆点亮、地图 zoom 15 —— 与现状「2、2 圆点、zoom 15」等价（仅数字位移）。
- 减到 L1：zoom 9、青岛全貌、减号禁用；继续手势缩小到 zoom 5：控件停在 1、行政聚合正常（国家/省点）。
- 加到 L7：zoom 17、加号禁用；手势放大到 18：仍 L7。
- 自由标记：进入锁 L7、退出恢复 6 与 zoom 15。
- 灵感/探索/已存模式：重渲染分支均传 `currentDetailLevel`，无需改动（逐一冒烟即可）。
- toast 新文案不溢出（沿用原格式）。

## 8. 风险与备注

- **数字位移**：既有用户看到的「Level 2」变为「Level 6」是本次唯一可见语义位移，属功能扩展的必然结果；圆点+数字的形态语言不变，且每次切换均有 toast 名称兜底，认知风险低。
- **12/13 两档相邻**：若冒烟时觉得两档视觉差异不够，可删 L4 降为 6 档（见 §3.2），改动仅为删一行档位表。
- **缩放绑定注释**（L4750-4753）需同步更新为新档位说明，避免后续维护误解。
