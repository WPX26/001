## 三、frontend.yml 核实结论（对照 HANDOVER 第 7 节）：**废弃**

结论：**`.github/workflows/frontend.yml` 已废弃，建议删除（或先停用）**，不需要修正。

理由（逐条对照 HANDOVER §7 实况链路）：

1. **部署链路不含 GitHub Actions**：实况 = `git push github master` → **阿里云 ACR 代码源自动构建**（ACR 代码源支持 GitHub/Codeup，不支持 Gitee）→ 王总在 Sealos「应用管理」点变更。frontend.yml 不在任何环节上。
2. **镜像目标地址与实况不符**：
   - frontend.yml 推送 `registry.cn-hangzhou.aliyuncs.com/memomap/memomap-frontend:*`（旧示例命名空间 memomap）和 `ghcr.io/wpx26/001/memomap-frontend:*`；
   - 实况仓库是 **青岛 cn-qingdao 个人版** `crpi-02avdj56c5eztlqi.cn-qingdao.personal.cr.aliyuncs.com/wpx001/static:latest`（前端）+ `wpx001/backend:latest`（后端）——两套地址完全对不上，产物无人消费。
3. **版本号漂移**：workflow 默认 tag `1.2`，与实况 `latest` 不一致，易误用。
4. **重复构建浪费**：保留它 = 每次前端 push 触发 Actions 构建 + ACR 代码源构建双份；且 Actions 构建失败还会造成「构建断了」的假警报。

修正方案（仅当王总想保留 GitHub 侧镜像产物时才需要，按当前链路**无必要**）：把地址改为 `crpi-02avdj56c5eztlqi.cn-qingdao.personal.cr.aliyuncs.com/wpx001/static`、tag 对齐 latest、去掉 GHCR 推送。**本文件未被修改**（按任务铁律仅核实）。
