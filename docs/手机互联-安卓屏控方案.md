# 手机互联 · 安卓屏控方案（2026-08-20 定稿）

> 王总要求：**打开本地相机的同时实现屏控** —— B 看 A 屏幕 + B 控制 A（像远程桌面一样随便点/滑 A 屏幕，含系统相机快门）。
> 双平台结论：**Android 自研完整屏控（本方案）**；**iOS 走 Facetime 引导**（Apple 无第三方触摸注入 API，Facetime 控制权是 Apple 自家功能，第 2 期做一键引导）。

## 1. 总体架构

```
┌─ A 机（Android，装我们 App）──────────────────────────────┐
│  connect.vue (web-view) ◄──evalJS──► 原生层(UTS 插件)       │
│    │ uni.postMessage                        ▲              │
│    ▼                                        │ dispatchGesture│
│  connect-prototype.html                    │              │
│    __plScreenFrame(frame)──WS frame──► B  │              │
│    touch 消息 ◄────WS touch──────┘          └──MediaProjection│
└──────────────┬────────────────────────────────────────────┘
               │ WS /api/v1/phonelink/ws?code=XXXXXX&role=host|client（后端原样透传）
┌──────────────┴────────────────────────────────────────────┐
│  B 机（网页浏览器，控制端）                                   │
│  connect-prototype.html                                    │
│    remote-frame 显示 A 屏帧（复用现有 frame 逻辑，零改动）      │
│    触摸层(plTouchLayer) → tap/swipe/longpress/back/home     │
└────────────────────────────────────────────────────────────┘
```

**关键设计**：帧与手势都走**现有 WS 通道**（消息原样透传，后端零改动）。
- A 端 App 录屏帧 → evalJS 注入网页 `__plScreenFrame` → 网页沿现有 `frame` 消息推给 B（B 端显示逻辑完全复用）
- B 端手势 → `touch` 消息 → 透传到 A 页 → uni.postMessage → connect.vue → UTS 插件 `dispatchGesture` 注入

## 2. 消息协议（业务自定义，后端透传）

| 消息 | 方向 | 内容 |
|------|------|------|
| `frame` | A→B | `{ type:'frame', data:<base64 JPEG dataURL> }` 屏幕帧（~5fps，宽=屏幕像素，q0.6） |
| `screen_on` | A→B | 屏控已激活，B 显示触摸层 |
| `screen_off` | A→B | 屏控停止，B 隐藏触摸层 |
| `touch` | B→A | `{ type:'touch', data:{ action, x, y, x2?, y2?, duration? } }` 坐标**归一化 0~1**（A 端按真实屏幕像素换算） |

`touch` 的 action：`tap` | `swipe` | `longpress` | `back` | `home`

## 3. 新增/修改文件

### 3.1 UTS 插件 `src/uni_modules/uts-screencontrol/`（Android 原生）
| 文件 | 作用 |
|------|------|
| `index.uts` | JS 侧 API 声明：startScreenShare/stopScreenShare/injectGesture/openAccessibilitySettings/isAccessibilityEnabled |
| `utssdk/app-android/index.uts` | 平台实现：透明授权页启动、帧回调接线、手势换算注入 |
| `ScreenShareRequestActivity.uts` | 透明 Activity：MediaProjection `startActivityForResult` 授权（UTS 无 onActivityResult API，自注册 Activity 方案） |
| `ScreenControlService.uts` | 前台服务（Android 14 mediaProjection 类型）：VirtualDisplay + ImageReader → RGBA→JPEG→base64 帧回调（200ms 节流） |
| `ScreenControlAccessibilityService.uts` | 无障碍服务：静态单例 + dispatchGesture（tap 80ms / swipe 300ms / longpress 600ms）+ performGlobalAction(back/home) |
| `AndroidManifest.xml` | 权限 + 三组件注册（FOREGROUND_SERVICE_MEDIA_PROJECTION / BIND_ACCESSIBILITY_SERVICE） |
| `res/xml/screencontrol_accessibility.xml` | 无障碍配置（canPerformGestures=true） |
| `config.json` | minSdk 24 |

### 3.2 App 桥 `src/pages/connect/connect.vue`
- `handleMessage` 新增：`pl_ready`（web 就绪，补推暂存帧）、`pl_screen_start/stop`、`pl_touch`、`pl_open_accessibility`
- `startScreen()`：调插件录屏，帧回调 → `evalJS("window.__plScreenFrame(...)")`（web 未就绪先入 pendingFrames 队列）
- `sendTouch()`：调插件 `injectGesture`
- `onUnload` 停止录屏

### 3.3 网页 `connect-prototype.html`
- **A 端（host）**：App 内显示「屏幕共享」按钮（`body.app-webview` 才显示）；`window.__plScreenFrame`（App 帧 → frame 通道）、`window.__plScreenStatus`（更新状态/发 screen_on/off）；屏控激活时停 getUserMedia 推流（帧源唯一）
- **B 端（client）**：remote-frame 内触摸层 `#plTouchLayer`（收到 screen_on 显示）+ 光标反馈 + 系统键「返回/主页」；指针事件 → tap（位移<3%）/swipe/longpress(600ms) → `touch` 消息
- host 收到 `touch` → `uni.postMessage` 转发 App（纯浏览器 host 忽略）

## 4. 真机验证步骤（王总两机）
1. A 机：App 联机页 → 手机互联 → 开始连接 → 点「屏幕共享」
   - 系统弹「开始录制或投射」→ 允许
   - 首次会提示开启无障碍：设置 → 无障碍 → 已安装的服务 → 地图相册 → 开启
2. B 机（任意手机/电脑浏览器）：联机页 → 手机互联 → 输 A 屏上的 6 位码
3. B 看到 A 全屏画面 → 点/滑/长按 → A 同步执行（打开系统相机、点快门等）
4. 拍照落 A 相册 → B 端相册角标 +1

## 5. 风险与边界
- **帧率**：首版 ~5fps（200ms），后续可降分辨率/提帧率；画质 60 可调
- **MediaProjection 安全限制**：Android 14+ 系统相机 App 可能因 secure flag 黑屏（个别机型）；可回退「我们 App 相机页全屏」方案
- **无障碍服务**：部分 ROM（MIUI/EMUI）需在应用管理额外允许「后台弹出/自启动」，否则手势注入失败
- **大字符串 evalJS**：每帧 100KB+ base64 经 evalJS 注入网页有开销，若真机卡顿改方案 B（插件直连 WS 或 WebRTC）
- **UTS 云打包**：需 HBuilderX 云打包（无本机 Gradle）；首次真机联调以云打包包为准
