# `uni-preset-vue-vite` 项目扫描结论

## 分析目标

说明目录 `uni-preset-vue-vite` 的整体功能、架构边界和主要调用链；本次不修改项目文件。

## 已确认的架构

- `src/main.js` 是 Vue 3 / uni-app 应用入口。
- `src/pages.json` 注册 9 个页面，默认入口为 `pages/home/home`。
- 本地壳层主要负责导航、系统相机、认证信息传递与 WebView 桥接。
- 地图相册、登录、消息、订阅等主要业务 UI 位于远程 HTML 页面；仓库不包含该远程页面和服务端的完整实现。
- `src/components/app-tab-bar/app-tab-bar.vue` 处理自定义底栏与相机拍照流程。
- `src/pages/home/home.vue` 处理首页 WebView、登录消息、拍摄照片 Base64 注入与 App 端 WebView 尺寸适配。
- `src/utils/request.js` 提供 Bearer Token、统一响应码和认证失效跳转能力，但不是首页远程 WebView 主流程的确定依赖。
- `src/uni_modules/ftp-receiver` 是未接入现有业务链的 UTS 原生 FTP 接收插件。

## 关键调用链

1. 应用启动：`src/main.js` 创建应用，`src/pages.json` 决定路由与页面样式。
2. 首页展示：`src/pages/home/home.vue` 组装远程页面 URL，必要时传入 token 和照片待挂载标记。
3. 拍照：`src/components/app-tab-bar/app-tab-bar.vue` 调用系统相机、压缩文件，并写入 `memo_pending_photo`。
4. 照片桥接：首页收到远程 WebView 消息后，读取临时图并在 App 端通过 `evalJS` 注入 Base64 数据；远端页面负责后续地图挂载与上传。
5. 认证：远端页面通过 `postMessage` 将登录结果发回，首页持久化 `memo_token` / `memo_user`。

## 注意事项

- token 以 URL 查询参数传入远程 WebView，存在被页面日志、历史记录或第三方脚本暴露的风险。
- 远程页面、接口服务和图片最终上传逻辑不在当前仓库，无法仅靠本地源码确认其真实运行行为。
- Android 配置含若干敏感权限，发版前需要逐项复核必要性。
- 页面普遍依赖线上 HTML；远端不可用或协议变动会直接影响 App 核心功能。
